# Minestom

Java library for custom Minecraft servers, without vanilla gameplay by default.

## General guidelines

- Do not edit `AGENTS.md` or `CLAUDE.md` unless explicitly asked.

## Tooling

- Use Java 25: Temurin for JVM work, GraalVM with Native Image for native tests.
- Run `mise install` to set up the JDK. Use `./gradlew`, or `mise exec -- ./gradlew` without mise shell activation.
- Gradle uses Kotlin DSL, `gradle/libs.versions.toml` for dependencies, and `build-src/` for shared conventions.

Run commands from the repository root:

| Task | Command |
| --- | --- |
| Compile core | `./gradlew :compileJava` |
| Run a test class | `./gradlew :test --tests 'net.minestom.server.inventory.InventoryCloseStateIntegrationTest'` |
| Run demo | `./gradlew :demo:run` |
| Regenerate sources | `./gradlew :code-generators:run` |

- Substitute the affected test class; use `:<module>:test` for subprojects.
- `src/autogenerated/java/` is checked-in generator output; do not edit it by hand.
- Regenerate only when the task requires generated changes. Check for existing edits first, update the responsible generator in `code-generators/` or its inputs, then run `./gradlew :code-generators:run`.
- Keep the current data dependency unless updating it is in scope. Preserve existing work and investigate any generated diff unrelated to your changes before including it.

## Verification

- Run affected tests. Use broader checks only when warranted; `.github/workflows/build-pr.yml` defines CI checks.
- Compilation runs Error Prone and treats warnings as errors. Fix issues rather than disabling checks.
- Use the lightest fixture; each class must pass alone:
  - `*Test`: unit tests.
  - `@RegistriesTest` / `*RegistriesTest`: registry snapshot.
  - `@EnvTest` / `*IntegrationTest`: server environment.
- Test the rule being changed: reproduce the triggering condition and assert its outcome and relevant side effects. For a bug fix, the test should fail with the bug present.

| Behavior | Good example | Weak coverage |
| --- | --- | --- |
| Border placement | [PlayerBlockPlacementIntegrationTest](src/test/java/net/minestom/server/entity/player/PlayerBlockPlacementIntegrationTest.java): clicking outside denies placement and interaction events, and sends corrections; clicking inside allows outward placement. | Setting/getting the border, or only checking that placement doesn't throw. |
| Inventory close | [InventoryCloseStateIntegrationTest](src/test/java/net/minestom/server/inventory/InventoryCloseStateIntegrationTest.java): a server close sends one packet; processing a later client close sends no extra packet. | Only checking that the inventory closed, missing the duplicate-packet regression. |

## Code style

- Follow `.editorconfig` and nearby code. Keep formatting changes local.
- Use JetBrains annotations and package nullability defaults.
- Preserve source and binary compatibility unless a breaking change is requested.
- Keep behavior with the state it owns. Protect valid state through methods; avoid exposing mutable internals.
- Split classes when responsibilities diverge. Add interfaces for real contracts or interchangeable behavior, not automatically for every class.
- Prefer composition. Use inheritance when subtypes honor the base type's contract.
- Respect thread ownership. Check concurrency and performance changes with relevant tests or benchmarks.

## Git

- Use Conventional Commits for commit messages and PR titles.
- Open PRs against `chunkzero/minestom-me`'s default branch (`master`), not upstream Minestom. Use `gh pr create --repo chunkzero/minestom-me --base master`.
- For explicitly requested upstream submissions, follow `.github/CONTRIBUTING.md`.

## Glossary

- **Instance:** an independently managed collection of chunks and entities.
- **Registry:** named game definitions, such as blocks, items, or entity types.
